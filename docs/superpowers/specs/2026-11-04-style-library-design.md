# 风格库（app.fordexa.com/library）设计

2026-11-04 · Shawn + Claude

## 为什么做

封面模板、转场、口播效果、版式件做完后散在好几个地方：Remotion Studio 的各个文件夹、评审页 5191、`组件参考.md`，还有 11-03 做的版式件，它们哪儿都没登记。Shawn 做片子时看不到有哪些可选，也说不出选项的名字，只能让 Claude 自己挑，挑错了就要多改一轮。

风格库是一个网页，所有选项都能看到在动的样子，每个配一个固定编号。Shawn 看中哪个就说「封面 K03、转场 T02」，Claude 照着编号做。以后把链接发给客户，客户看完能说出自己喜欢什么、不喜欢什么。库会一直往里加：做片子时顺手做出好用的效果，或者看到别人的好效果照着做的。

草稿已经试过（`src/app/studio/library/page.tsx` + `public/library-draft/`，没有提交）：41 个选项，按 0.5 倍渲染，一共大约 4 分钟、6 MB。名字和说明直接从 xhs-video 的 catalog 读，不用重写。

## 目标

1. 一个页面，按分组列出所有可用的选项。封面显示定格图，动效显示循环播放的小视频。每个选项都有编号、名字和一句用途说明。
2. 编号永远不变。新加的选项接在后面编号，删掉的编号作废，不挪给别的选项。
3. 加一个新选项只需要两步：在登记表里加一行，然后跑一条命令。页面自动更新，不用改网站代码，也不用重新部署。
4. 不用登录，不用密码，有链接就能看。

## 不做的

- 不在页面上点选并「记到某条片子上」。Shawn 只需要把编号说出来。
- 不放客户品牌版。用客户的颜色、照片做的效果，走主页预览的分享链接（`docs/superpowers/plans/2026-10-23-showcase-share-link.md`）。客户的照片要她本人同意才能用，所以不能放进人人都能看的库里。
- 不在页面上评分，评分照旧用评审页 5191。
- 不在页面上调参数（换字体、换颜色）。

## 绝对不能出现的情况

- 同一个编号前后指向不同的东西。
- 页面被搜索引擎收录。
- 评过「弃用」的组件出现在库里，比如手绘那一轮、硬切、黄条扫过。
- 库里出现客户的品牌或照片。

## Shawn 定的

- 放在 app.fordexa.com，也就是 promptcam-web，地址在工作台外面：`/library`。
- 不用登录，不设密码。只要求不被搜索引擎搜到。
- 用法是告诉 Claude 编号，页面上不做点选。
- 先给自己用，以后发给客户看喜好。
- 新内容有两个来源：自己做片子时用得好的，和参考别人的效果做的。

## Claude 定的（Shawn 可以改）

**分组和编号前缀**

| 分组 | 前缀 | 内容 |
|---|---|---|
| 模板封面 | K | KitCover，每种版式至少一张样张 |
| 实拍封面 | P | PhotoCover，小夏版、Shawn 版、换字体版 |
| 转场 | T | catalog 第 3 轮 |
| 口播效果 | E | catalog 第 7 轮 |
| 素材卡片 | M | catalog 第 4 轮里通用的卡片：关键词卡、流程条、场景排、录屏卡片、实拍手机、点击提示、额度阶梯、字幕 |
| 版式件 | L | 11-03 的 Panels（横条、竖柱、大数字、清单）、SourceShot（截图卡 + 红框）、PageStage（按官网一页讲）、Tag 中文翻译卡 |

- 编号格式是「前缀 + 两位数字」，比如 K01、T02，超过 99 个就自动变三位。草稿里的编号作废，正式版按登记表重新排一次，从那以后固定。

**登记表**
- 登记表是 xhs-video 里的一个文件，比如 `library/registry.json`。每行记：编号、分组、来源（catalog 的组件 id，或者某张封面样张的名字）、出处、加入日期，以及是否已经下架。
- 出处写这个选项是怎么来的，比如「FX-0034 用过」或者「参考：某账号某条」。
- 名字和用途说明从 catalog 或封面样张里读，登记表不重复写，只在需要时写一个覆盖值。
- 下架的选项留在登记表里，打上下架标记，页面上不显示，编号也不再用。
- 只要组件在评分里的最新结论是「弃用」，就不能登记。按组件 id 取最新的一条，不管是第几轮评的。

**缺的样片**
- 版式件、素材卡片里还没有样片的，要在 xhs-video 里补样片 composition。照 catalog 现有的写法：人像加真实口播加字幕。
- KitCover 里还没有样张的版式（步骤、清单、时间窗、表格）也要补样张。可以借 Vtax 那 20 张封面的结构，但颜色和人物用王小墨的，话题用王小墨自己的。

**流程，拆成两步**
- **xhs-video 负责渲染**：一个脚本读登记表，只渲染新增的或者被要求重渲的选项。封面出 jpg；动效出静音 mp4，加一张定格图做封面。全部按 0.5 倍尺寸。输出到一个本地文件夹，再生成 `manifest.json`。
- **promptcam-web 负责上传**：一个脚本把这个文件夹和 manifest 上传到 Supabase 的公开存储桶 `style-library`。存储的密钥只放在 promptcam-web 里，xhs-video 不碰。
- 上传前先列出这次要上传、要替换、要下架的选项，给 Shawn 看，Shawn 确认后才真传。这跟 showcase-import 先 `--dry-run` 是同一个习惯。

**媒体存放**
- 图片和视频放在 Supabase 存储里，不进 git 仓库。库会越来越大，每次重渲都往仓库里塞视频不划算。

**页面**
- 页面由服务端读桶里的 manifest，缓存几分钟。库更新后，几分钟内页面就跟着变。
- 外观沿用草稿：顶部按分组筛选，网格排列，点一下复制编号。手机上两列。
- 页面只读，没有工作台导航，最下面一行写 Fordexa。

**不被搜索引擎收录**
- 页面 metadata 设 `robots: noindex, nofollow`。
- `robots.ts` **不** disallow `/library`（2026-11-04 审稿后改：被 robots.txt 挡住的页面爬虫不会抓，也就读不到 noindex，链接被公开转发时反而可能以裸网址被收录）。
- 不进 sitemap。入口只有全站页脚的「风格库」（2026-11-05 Shawn 改：原来是哪里都不链接），页头和首页正文不放。

**收尾**
- 正式版上线后，删掉草稿：`src/app/studio/library/`、`public/library-draft/`，还有 xhs-video 的 `tmp/library-draft/`。

## 审稿后补充（2026-11-04，都是 Claude 定的）

**什么能进库**
- 「弃用」指 `组件评分.jsonl` 里的 `drop`。
- 按组件 id 取文件里**最后一行**的结论，不管它是第几轮评的：
  - `keep` 能进；
  - `fix` 和 `drop` 都不能进；
  - 没有评过分的（封面样张、版式件）能进。
- 登记脚本每次跑都要按这条规则检查一遍。不合格的选项直接报错，不能悄悄跳过。
- 素材卡片（M）具体是这些 catalog id：`d-caption-box`、`d-keycard`、`d-flow`、`d-scenes`、`d-phone`、`d-real`、`d-shortcut`、`d-quota`。`d-app`（App 介绍卡）和 `d-end`（结尾卡）只适用于谛听这一个产品，不放进来。
- 第 2 轮「风格选型」是在选整体方向，不是组件，所以不进库。

**编号绑的是哪一个「选项」**
- 一个编号对应的是一个选项，不是某个版本。原地改好看一点，还算同一个选项，编号不变，重新渲染就行。
- 改成了明显不同的东西，就给新编号，把旧编号下架。
- 组件的 id 改名了，要手动改登记表。登记表里写的来源 id 在代码里找不到时，脚本直接报错，不能静默跳过。

**草稿编号**
- 草稿编号只在 11-04 这一次对话里出现过，没有写进任何视频笔记。正式版直接从头编，不用处理旧编号。

**样片怎么做**
- 动效全部渲染成静音视频，所以不需要配音。
- 人像统一用 catalog 现有的 `public/samples/person.mp4`。
- 版式件（L）的样片内容取自最先用到它的那期片子（11 月那一批 FX-0034–0050），数字照旧标「示意」。
- 封面样张的来源名就是 `src/covers/samples.ts` 和 `photoSamples.ts` 里的 key，这些 key 已经固定了。
- 新补的 4 张 KitCover 样张，key 也写进这两个文件。

**公开存储**
- 文件名是可以猜到的，Shawn 接受这一点。库里只有王小墨自己的东西：小夏是 AI 照片，Shawn 本人本来就公开出镜。
- 上传脚本加一道检查：选项的来源只要用到 `src/covers/brands/` 里不是王小墨的品牌，或者用到 `public/covers/` 里客户的照片包，就拒绝上传。

**名字和用途说明**
- catalog 里没有的名字和说明，由 Claude 照现有的写法用中文写进登记表，Shawn 在页面上看到不对再改。

**页面怎么更新**
- 服务端用 `fetch` 读桶里的 manifest，加 `next: { revalidate: 300 }`。库更新后，最多 5 分钟页面就跟着变，不用重新部署。

## 留给实现的人

- 存储桶里的目录结构，以及 manifest 的字段。
- 页面缓存时间具体多长。

- 两个仓库都要等 Shawn 说「提交」才能 commit。存储桶怎么创建、权限怎么设，先给 Shawn 看再执行。
- 画面上不出现网址或域名（内容家规）。样张里的数字照旧标「示意」或「draft」。
